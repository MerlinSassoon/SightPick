# 案例：BOSS直聘岗位采集

> 这是 SightPick 的**第一个案例**，不是系统边界。
> 页面结构、坐标和停止条件都会变化；本文档只描述当前案例的配置思路与已知问题。
> 不包含真实截图、公司名、招聘者姓名或联系方式。
>
> 📌 **最新现场复盘（2026-10-24）**：大批量运行（381 条）确认了两个本文档 §4.4 未覆盖的机制——
> ① 锚点失败的**真实成因**多为滚动坐标漂移与点击后白屏，而非 OCR 漏识；
> ② 重复条目的根因是平台"**无限加载 + 已读置灰**"，视觉 RPA 无法识别置灰状态。
> 详见 [TEST_REPORT_20261024.md](TEST_REPORT_20261024.md)。

## 1. 为什么选这个页面

BOSS直聘的岗位页同时具备：

- 左侧岗位列表（可滚动、可点击）；
- 右侧岗位标题/薪资/标签（短文本）；
- 右侧职位描述（长文本、可滚动、动态加载）；
- 大量界面噪声（去App、招聘者卡片、工作地址、标签、按钮）。

它适合验证两种通用模式：

- **列表导航**：点一条，读右侧；
- **区域抄录**：读标题/描述，滚动、去重、停止。

同时，它也暴露了视觉 RPA 的典型难点：坐标、DPI、滚动距离、动态加载、OCR 错字、停止条件。

## 2. 页面区域

参考配置：`configs/boss_1080p_example.json`，基于 1920×1080、100% 缩放。

| 区域 | 位置 | 内容 | 模式 | 说明 |
| --- | --- | --- | --- | --- |
| A | 左侧列表 | 岗位名、薪资、标签、公司、地点 | 列表导航（`sms`） | 点击列表项，调用 B/C |
| B | 右侧标题带 | 岗位标题、薪资、标签 | 区域抄录（`transcribe`） | 作为字典键；当前问题最多 |
| C | 右侧描述区 | 职位描述、招聘者信息、地址 | 区域抄录（`transcribe`） | 可滚动；停止条件待改进 |

区域坐标只是示例，不是通用值。换分辨率/DPI/浏览器缩放后必须重新框选。

## 3. 当前配置思路

### A：列表导航

- 滚动距离：负值，向下滚动；
- 滚动起点：列表内一点；
- 停止标志：页面底部出现“企业服务”“使用与帮助”等；
- 调用区域：先 B（键），再 C（值）；
- 数据结构：字典模式；
- 点击确认：默认关闭；开启会增加 LLM 调用与回滚。

### B：标题抄录

- 不滚动；
- `expected_content = 岗位名称`；
- `expected_format = str`；
- 作为字典键。

**当前问题**：B 区域实际包含标题 + 薪资 + 标签，LLM 有时把薪资拼进标题，有时把“AI 方向”等后缀清洗掉，导致标题不稳定。

### C：描述抄录

- 可滚动；
- 滚动起点在描述区内；
- 停止标志：早期用“工作地址/去App/先生”，后期收敛为 `去App`；
- `expected_content = 职位标签和职位描述`；
- `expected_format = list`；
- 首轮锚点：`职位描述`。

**当前问题**：`去App` 是页面按钮，不是内容结束语义；锚点首轮漏识会终止整批。

## 4. 真实运行中观察到的现象

### 4.1 能跑通

- 真实屏幕点击/滚动/截图；
- PaddleOCR 识别标题、标签、描述、地址；
- DeepSeek 做锚点确认/纠错、去噪；
- 3–5 条小批量可稳定跑；
- 最近连续 5 次成功，19 条，0 warning。

### 4.2 标题不稳定

脱敏示例：

- 只剩 `10-15K`；
- `应用工程师 10-15K`；
- `件工程师（A方向）`；
- `据开发工程师`；
- 页面 `Python 开发工程师（AI 方向）` → 输出 `Python开发工程师`（方向丢失）。

### 4.3 描述不干净

- `职位描述`/`岗位职责`/`任职要求` 标题行；
- `工作地址` + 地址；
- `标签：...` 标签行；
- 招聘者姓名/“刚刚活跃”状态；
- `去App`/`与BOSS随时沟通` 按钮文案。

### 4.4 锚点失败

首轮 OCR 没有“职位描述”时，交给 LLM 确认；LLM 说“不存在”就终止整批。
真实运行中，这是 0 条记录的最主要原因。

### 4.5 停止条件风险

`去App` 进入 C 区域就停止；有记录在第 1 轮命中后只有 9/11 行描述。
不能断言一定截断，但停止条件与内容语义脱钩。

## 5. 校准步骤（换屏幕/换页面时）

1. **固定环境**：1920×1080、100% 缩放、浏览器最大化；关闭会弹窗的插件；
2. **截首屏**：用倒计时模式，避免最小化命令行；
3. **框选 A/B/C**：A 只框列表，B 只框标题带，C 从“职位描述”标题下方开始；
4. **测滚动**：用滚动测试看首尾是否重叠、有无缺行；
5. **设停止**：优先用内容语义标志，不要只用 UI 按钮；
6. **跑 mock**：确认区域/调用/输出映射；
7. **跑 1 条真实**：检查标题、描述、锚点、warning；
8. **再跑 3–5 条**：检查重复、截断、PII；
9. **记录结果**：填入 [EVIDENCE.md](EVIDENCE.md) 的 benchmark 表。

## 6. 已知问题与建议

| 问题 | 当前表现 | 建议 |
| --- | --- | --- |
| 标题混入薪资/标签 | `10-15K`、`应用工程师 10-15K` | 把 B 拆成标题/薪资/标签子区域，或做结构化解析 |
| 标题过度清洗 | `Python开发工程师` 丢失“AI方向” | 保留原始 OCR 行 + 清洗后标题两个字段，便于回溯 |
| 描述噪声 | 标题/地址/标签/PII | 规则层强制过滤，不只依赖 LLM |
| 锚点失败 | 首轮漏识即终止 | 重试/等待/滚动一屏；失败可跳过当前岗位 |
| `去App` 停止 | 第 1 轮可能提前结束 | 改用“工作地址”/内容长度/滚动上限组合 |
| PII | 招聘者姓名/状态进入描述 | 输出前过滤；截图不默认留存 |
| 20 条未验收 | 最多 5 条 | 先做 20 条 ground truth，再谈产品 |

## 8. 这个案例的边界

- 它证明“视觉 RPA 能在 BOSS 上跑”，不证明“视觉 RPA 是 BOSS 的最优方案”；
- 它证明“3–5 条小批量可稳定”，不证明“20 条/多页面稳定”；
- 它证明“两种模式可组合”，不证明“多领域已经复用”；
- 它是工程样品的一个案例，不是产品承诺。
