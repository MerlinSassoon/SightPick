# 演示脚本：90 秒 / 5 分钟

> 目标：让面试官在最短时间内看懂“这是视觉 RPA 工程样品，不是招聘爬虫 demo”。
> 原则：先讲问题与架构，再展示 mock 链路，最后用**脱敏聚合证据**讲真实运行；不要展示真实截图/PII。

---

## 1. 90 秒电梯陈述

> “SightPick 是一个视觉 RPA 工程样品。它解决的是‘系统没有 API/DOM，但人还得从屏幕里抄数据’的问题。
> 做法是：用户框选界面区域，程序截图、OCR、用视觉大模型做语义确认和去噪，最后把结构化记录逐条落盘。
> 当前拿 BOSS直聘做第一个案例，用两种通用模式：列表导航 + 区域抄录。
> 真实链路已经跑通：7 次 real + DeepSeek 成功批次，最近连续 5 次 19 条、0 warning。
> 它还不是产品：标题/描述质量、20 条验收、PII 合规都还没完成。
> 我想证明的是：这套抽象能迁移到其他没有 API 的桌面系统，而不是只服务招聘。”

---

## 2. 5 分钟演示流程

### 0:00–0:40 问题与定位

- 目标系统没有 API/DOM；人工复制慢、易错；
- 视觉 RPA 的适用边界：遗留系统、内部工具、多步骤视觉流程；
- 不是“更高级的爬虫”，是“接口不存在时的最后手段”；
- 当前案例：BOSS直聘；核心抽象：列表导航 + 区域抄录。

### 0:40–1:40 架构

展示 `docs/ARCHITECTURE.md` 的图：

```text
GUI → ScreenDriver → OCR → Modes（list/transcribe）→ LLM（确认/去噪）→ JSONL
```

强调：

- 驱动/OCR/LLM 可替换；
- 领域差异在配置层；
- mock 与真实共享同一套编排；
- 异步 worker 有有界队列与单一屏障。

### 1:40–2:40 mock demo

```powershell
python run.py demo
```

展示：

- `jobs.jsonl`；
- `capture_report.json`；
- 不移动鼠标；
- 3 条记录、`list_end`、无重复行。

说明：这是“可重复的链路验证”，不是真实效果。

### 2:40–3:40 真实运行证据（不展示原始数据）

打开 `docs/EVIDENCE.md`：

- 24 次运行 / 35 条真实记录；
- 7 次 real + DeepSeek 成功；
- 最近连续 5 次：19 条、约 367 秒、0 warning；
- 35 条描述 0 重复行；
- 但：16/35 标题有明显缺陷、33/35 描述有噪声/PII/过短。

强调：**“能跑”与“能用”是两件事。**

### 3:40–4:30 已知问题与取舍

- 标题混薪资/截断 → B 区域需要结构化拆分；
- 描述噪声/PII → 规则兜底 + redaction；
- 锚点失败 fatal → 重试/等待/跳过；
- `去App` 停止 → 内容语义/长度保护；
- 20 条/成本/ground truth 未完成；
- 107 张真实截图 → 本地留存，不能上传。

### 4:30–5:00 下一步

- 20 条 ground truth + 标题/描述达标；
- PII redaction；
- 第二个领域只改配置验证复用；
- 再决定做“授权 RPA”还是“求职分析”。

## 3. 演示时不要做的事

- 不要打开 `runtime/` 或真实截图；
- 不要展示公司名、招聘者姓名、联系方式；
- 不要展示 `.env` / API Key / 终端历史；
- 不要把 24 次调试运行说成“24 次成功”；
- 不要把 5 条说成“可规模化”；
- 不要承诺“页面改版零维护”。

## 4. 面试官可能追问

1. 为什么不用 DOM/Playwright？
   → 视觉 RPA 适合没有 API/DOM 的系统；对 BOSS 是“能跑”，不是“最优”。需要成本/准确率对比。

2. 20 条为什么没跑？
   → 当前最多 5 条；锚点/停止条件/质量还没达标；下一步先做 ground truth。

3. 标题为什么会出现 `10-15K`？
   → B 区域包含标题+薪资+标签；兜底选最长行；需要结构化拆分与硬约束。

4. 锚点失败为什么是 fatal？
   → 当前首轮确认失败即抛错；应重试/等待/跳过。

5. 真实截图怎么处理？
   → `runtime/` 不入库；公开只用聚合指标；未来默认不持久化截图。

6. 这套东西能迁移到别的领域吗？
   → 执行层是领域无关的；领域差异在配置/文案/输出 schema；需要第二个领域验证。
