# 真实运行证据（脱敏）

> 这份文档只放**聚合指标与脱敏示例**，不包含真实页面截图、公司名、招聘者姓名、联系方式或原始 `jobs.jsonl`。
> 原始数据在本地 `runtime/`，已被 `.gitignore` 排除；原因见 [PRIVACY.md](PRIVACY.md)。

---

## 1. 为什么单独写一份证据文档

SightPick 的公开仓库里，代码和 mock demo 都能看到，但“真实页面到底跑没跑通”很难从代码判断。
本地 `runtime/` 里有真实运行记录，但它同时包含：

- 真实页面截图（含招聘者姓名/头像/公司）；
- 岗位描述原文（可能含公司名、地址、招聘者信息）；
- 运行日志中的页面路径。

这些不适合直接上传。于是把**可公开的部分**抽出来：

- 运行次数、条数、耗时；
- LLM 调用次数、warning 数；
- 失败分类；
- 标题/描述质量的聚合统计；
- 不含 PII 的少量示例。

这样既不泄露数据，又能让评审者看到“真实跑过”。

## 3. 稳定批次：最近连续 5 次成功

从 `15:07` 到 `16:07`，同一页面、同一分辨率、同一配置下，连续 5 次真实运行成功：
（`150721` → `151125` → `152004` → `154834` → `160702`）

| 指标 | 合计 |
| --- | ---: |
| 记录 | 19 条 |
| 耗时 | 约 367 秒 |
| 平均 | 约 19.3 秒/条 |
| warning | 0 |
| 锚点失败 | 0 / 5 |

这 5 次都是 `engine=real`、`llm=deepseek`，单次 3–5 条。
它能证明：**在固定页面/固定配置下，基础链路可以稳定跑出小批量数据。**

它不能证明：**20 条、不同页面、不同分辨率、不同账号下仍然稳定。**

## 6. 数据质量审计

对 35 条真实记录做规则审计（不包含 demo 的 3 条）：

### 6.1 标题

| 指标 | 结果 |
| --- | ---: |
| 明显标题缺陷（严格口径） | 至少 16 / 35（约 46%） |
| 如果算上泛化标题 | 约 21 / 35（约 60%） |
| 标题混入薪资 | 9 条 |
| 明显截断/OCR 缺字 | 9 条（与薪资有重叠） |

脱敏示例（都是岗位标题，不含个人信息）：

- 只剩 `10-15K`；
- `应用工程师 10-15K`；
- `件工程师（A方向）`；
- `据开发工程师`；
- `ai应用开发工程师 12-20K`。

另一个更微妙的问题是“过度清洗”：

- 页面：`Python 开发工程师（AI 方向）`；
- 输出：`Python开发工程师`。

方向信息丢了，薪资也没有进入 `salary` 字段（仍为 `null`）。
所以标题问题不只是“有噪声”，还包括“清洗掉了有用信息”。

### 6.2 描述

| 指标 | 结果 |
| --- | ---: |
| 至少含 1 行噪声/PII/过短的记录 | 33 / 35 |
| 噪声行总数 | 68 行 |
| 招聘者信息行 | 12 行 |
| 描述 ≤ 11 行的记录 | 4 条 |
| 描述重复行 | 0 |

典型噪声（聚合描述，不引用原文）：

- `职位描述`、`岗位职责`、`任职要求` 等标题行；
- `工作地址` + 地址、公司名；
- `标签：Python、...` 标签行；
- 招聘者姓名/“招聘者”/“刚刚活跃”等状态行；
- `去App`、`与BOSS随时沟通` 等界面元素。

**去重是成功的**：35 条记录 0 重复行。
**清噪是不稳定的**：描述清噪主要依赖 LLM，规则层不是强制兜底；因此“看起来有 20 行”不等于“20 行都是职位描述”。

### 6.3 停止条件

C 区域当前主要靠 `去App` 停止。它是页面按钮/入口，不是“职位描述结束”的语义标志。

日志中：

- `154834` 第 3 条：第 1 轮命中 `去App`，描述 9 行；
- `160702` 第 3 条：第 1 轮命中 `去App`，描述 11 行；
- `152004` 三条都在第 2 轮命中 `去App`。

不能断言这些一定被截断（有的岗位描述本来就短），但这是一个明确的高风险设计：**停止条件与内容语义脱钩**。

## 7. 这份证据能证明什么

**能证明：**

- 真实屏幕截图/点击/滚动可用；
- PaddleOCR 在真实页面上可用；
- DeepSeek 真实调用可用；
- 异步 worker、重试/降级、JSONL 落盘在真实批次中可用；
- 固定页面/固定配置下，3–5 条小批量可稳定跑；
- 描述去重有效（0 重复行）。

**不能证明：**

- 标题/描述已经达到“可直接分析”的质量；
- 20 条连续采集稳定；
- 不同页面/账号/分辨率下稳定；
- 单条成本、token 费用、失败率满足产品要求；
- 合规/授权已经解决。

## 9. 如何复现（不依赖本仓库的 runtime）

1. 在 Windows 桌面、固定分辨率/DPI 下准备目标页面；
2. 按 [RUNBOOK.md](RUNBOOK.md) 截图、框选、配置滚动/停止/锚点；
3. 先跑 mock，再跑 1 条真实样本；
4. 用 3–5 条小批量验证链路；
5. 做 20 条 ground truth 标注；
6. 用 [PRIVACY.md](PRIVACY.md) 的检查表处理截图/文本，再决定是否公开聚合结果。

> 本仓库不提供真实运行数据；`runtime/` 永远不应提交。
> 可公开的 schema 示例：[data/samples/sanitized/jobs.jsonl](../data/samples/sanitized/jobs.jsonl)（合成数据，不是真实记录）。

## 10. 证据边界

- 这些数字来自作者本地的一次真实运行集合，不是第三方复现实验；
- 页面、账号、分辨率、时间都会影响结果；
- 标题/描述质量审计是规则启发式 + 人工抽查，不是完整的人工 ground truth；
- 因此本文档的定位是“可信的工程证据”，不是“学术评测”或“商业 SLA”。
